# 可复现验证样例

先按照 README 安装并启动；初始使用空数据目录。不需要 API Key。所有演示资料都是虚构样例，演示中的覆盖率、性能与“评测通过”不代表本作品实测数据。

1. 打开 `http://127.0.0.1:8000/`，点击“载入演示数据”。系统独立创建“示例团队项目”，写入 4 条进展，分别包含 1 条普通进展、2 条代码记录与 1 条评测记录。再次导入不增加重复记录。
2. 进入“交接查询”，选择“示例团队项目”，输入 `用户认证`，点击“查询交接上下文”。预期返回 2 条记忆命中与 2 条来源引用，prepared context 为 `ready`。
3. 展开“完成用户认证模块”来源，可看到原文、`progress_id`、SDK 原生 `source_ref`、`memory_ref`、`entry_id` 与 `entry_version_id`。实际运行快照见 `evidence/handoff-sample.json`；标识由运行时生成，重新初始化数据后允许变化。
4. 进入“技术证明”，可核对本次查询返回的原生来源与记忆标识。最近进展被另行标注“非查询匹配”，不会当作命中证据。
5. 进入“版本对照”，选择示例项目。最新代码为 `optimize/db-queries` 分支，最近评测为 `feature/auth` 分支，应显示“有未评测更新，分支不同，commit 不同”。应用不会自动提交评测，也不会自动将新版本认定为已评测。
6. 停止服务并以同一个数据目录重新启动。再次执行第 2–3 步，原记录仍能被检索和引用。独立测试使用关闭/重新打开的真实 SDK，验证了这一行为。
7. 新建另一个项目，写入 `仅第二项目可见`。在第一个项目中查询该短语，不得返回第二个项目的记忆或来源。无匹配时允许展示明确区分的最近进展，不声称有匹配。

实际本地截图位于 `site/images/`。展示站为静态作品介绍，完整应用按上述说明在本机运行。
