团队交接上下文管理
基于 OceanBase PowerContext SDK 构建的本地 Web 应用，让团队成员记录进展， 并在下一次工作时通过 PowerContext 恢复有来源的项目上下文。

真实痛点

交接混乱

小型开发、学习或竞赛团队在交接时需要反复从聊天整理"已完成什么、下一步做什么、哪个版本经过验证"。

版本混淆

尤其容易把最新代码版本误当成平台已经评测过的版本，导致重复工作或错误判断。

上下文丢失

项目进展、决策依据、评测结果散落在各处，新成员难以快速了解项目全貌。

PowerContext 的实际作用

RelayDesk 实际使用 PowerContext SDK， 使用其 builtin runtime 和 SQLite backend 实现核心的记录、来源追溯和上下文复用能力。

所有数据通过 PowerContext 的 Scope、Source、Memory 和 Context API 进行管理， 确保数据持久化、项目隔离和有来源引用的上下文检索。

使用的 PowerContext API

  • Scope 管理：每个项目对应一个独立的 Scope，实现数据隔离
  • Source 捕获：进展记录作为 durable Source 存储，保留完整历史
  • 确定性 candidate_pipeline + flush：通过自定义 ProgressContentPipeline 将 ContentSource 转换为 MemoryEntryInput，保留原生 SourceRef 链路
  • Memory 搜索 (FTS)：使用 SQLite 全文搜索检索已保存记录
  • Context Preparation：查询时准备有来源引用的上下文
  • Records API：通过 current_memory_entry().sources 和 get_source() 追溯原始来源

技术特点

  • 使用 PowerContext builtin runtime，无需外部服务
  • SQLite backend，数据本地持久化
  • 确定性来源整理，不需要外部 LLM Key
  • 真实 API 调用，非 mock 或 fallback
  • 数据重启后可恢复，项目间完全隔离
  • 原生 SourceRef 链路，非手工构造

本地运行

主要应用代码由 Qoder CLI 开发，Codex 完成独立验收和部分 QA 修正。已验证 12 项独立测试通过；尚未申报平台得分或真实用户提效数据。

1

克隆仓库

获取源代码：

git clone --branch 2026-competition-ecosystem --single-branch https://github.com/Client-Qv0/cpt-powercontext.git cd cpt-powercontext/qoder
2

安装依赖

确保已安装 Python 3.12 和 Git，然后安装依赖（包含 PowerContext SDK）：

python3.12 -m venv .venv source .venv/bin/activate python -m pip install -r backend/requirements.txt

PowerContext SDK 通过 requirements.txt 固定到公开 Git revision 安装：

powercontext[builtin] @ git+https://github.com/Client-Qv0/cpt-powercontext.git@6d56d1ae5a0f944e04f70233d04f2b8c010b1f7b
3

启动服务

运行启动脚本：

python run_server.py

服务启动后访问 http://127.0.0.1:8000/

4

验证功能

运行独立验收测试验证完整工作流：

python -m pytest -q tests/test_independent_acceptance.py
