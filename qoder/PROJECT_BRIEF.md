# RelayDesk 接力台 — Qoder 开发任务书

这是需求规格，不是已完成实现。主要应用代码、测试、调试和站点页面须实际在 Qoder 中开发，并保留真实会话记录。不得伪造 Qoder 开发截图、上线地址、访问量、用户评价或技术调用记录。

## 用户与问题

小型开发、学习或竞赛团队在交接时需要反复从聊天整理“已完成什么、下一步做什么、哪个版本经过验证”。尤其容易把最新代码版本误当成平台已经评测过的版本。做一个可本地运行的中文 Web 应用，让成员记录进展，并在下一次工作时通过 PowerContext 恢复有来源的项目上下文。

名称：RelayDesk 接力台。界面说明用简体中文。产品应完成真实的“记录进展 → 保存至 PowerContext → 关闭/重新打开应用 → 查询并复用交接上下文”闭环。

## 核心功能

1. 项目列表及进度概览；可以创建项目，按项目隔离数据。
2. 项目内新增进展记录：标题、正文、负责人（可选）、状态、下一步、记录时间。另支持记录代码分支、完整 commit 和评测结果。
3. 分开展示“最新代码版本”和“最近评测版本”。二者不同就显示“有未评测更新”；从未评测要明确显示。没有任何自动提测功能。
4. 查询或恢复交接：输入问题，使用 PowerContext 的真实来源/记忆/上下文接口检索已保存记录，给出有来源引用的交接摘要，包括当前进展、下一步和最近评测事实。引用可展开原文；没有证据时明确说未记录。默认不需要外部 LLM Key，也不把模板摘要冒充模型生成。
5. 技术证明面板：显示本次 PowerContext 操作实际返回的来源或记忆标识、查询/上下文结果及时间。面板引用实际 SDK 返回值，不生成装饰性的假调用日志。PowerContext 异常时返回可理解错误，不静默退化成普通 JSON 文件搜索。
6. 仅在用户点击“载入演示数据”后导入完全虚构、明确标注的样例团队资料；重复导入幂等。导入、重启和检索均能通过运行步骤验证。可复制/下载当前交接摘要。

## 技术与实现约束

- 实际使用 PowerContext 为核心记录、来源追溯和后续上下文复用提供能力，不允许仅测试连接或只在文案中提到该技术。
- 优先使用 Python 3.11+、FastAPI、静态 HTML/CSS/JavaScript 和 PowerContext 的本地 SQLite 后端。避免为展示引入复杂前端构建依赖；可以按实际需要调整。
- 直接依赖真实 PowerContext，固定到可复现的版本或 Git commit；注明上游项目、许可证和采用的接口。可先阅读相邻 powercontext-submission 的公开源码、示例、测试作为 API 参考，不能修改它，也不能把只在开发电脑有效的绝对路径写入最终依赖。
- SDK 可能使用 runtime/scope/source/artifact 等概念；先查看当前版本公开接口，再实现最小可运行纵向链路，不能猜造 SDK 方法。若记忆抽取默认需要外部推理服务，应选择 SDK 支持的显式记忆/来源与上下文组合方式，说明其作用，不绕过 PowerContext 自造同名对象。
- 功能数据持久化并在重启后可恢复；多项目查询不能泄漏其他项目的记录。前端使用 textContent 或可靠转义，防止进展正文作为 HTML 执行。服务默认只监听本机，不含密码、令牌或真实个人资料。
- 外部推理可以是未来扩展，但本次基础流程不得依赖未配置的付费模型 Key。不要安装或配置其他第三方账号。
- 工作仅限本仓库 qoder 目录。gaode、其他生态伙伴目录、master 和原答题分支不改动。不操作比赛网页、不提交平台评测、不调用 GitHub 写操作、不自行 commit/push，不启动其他 Agent 或并行会话。

## 视觉与体验

做成精致、易用的工作台：深蓝侧栏、浅色主画布、暖橙色重点状态，卡片和清晰的留白。桌面和手机均能使用；选中项目、搜索、加载、失败、空结果和新增成功均有明确反馈。不要在初次进入时显示伪造的真实用户统计。

重点页面：项目概览；时间线与新增进展；交接查询与原文引用；代码/评测版本对照；PowerContext 操作证据。可采用单页工作台，不追求无用的页面数量。

## 验收与测试

请实际安装依赖、启动并验证最小闭环，然后补充有价值的测试。重点：真实 PowerContext 的持久化与重启恢复、项目隔离、检索结果与原文对应、空查询与无结果、评测版本状态、演示数据幂等、无 Key 启动、输入边界与错误处理。测试不能仅 mock 掉核心 PowerContext 集成。

提供至少一组完整复现步骤，包含初始数据、输入、操作、预期结果、实际 PowerContext 标识和重启后的复用。演示资料使用虚构版本号/commit，并明确是样例，不使用本队真实评测结果来编造功能成功。

交付文件应包含：完整源码、固定依赖、README 安装到启动步骤、验证样例及测试说明、第三方来源声明、配置示例（只含占位值）、适当的忽略规则。使用真实执行结果说明限制，未执行的检查写明未执行。

## Qoder Sites 展示站

核心应用先在本地完整运行。之后用 Qoder 制作 site 目录下的可发布展示站，包含项目简介、真实痛点、核心功能、实际应用截图位置、PowerContext 的实际作用、代码仓库链接和本地运行/复现入口。网站仅作为作品展示和评审入口，不能把静态演示伪装成实时 PowerContext 服务。

必须通过本账号的 Qoder Sites 发布，不能用其他 Sites 产品替代。当前阶段先完成页面与本地预览，不发布、不改变访问策略。之后由用户看过作品再继续发布流程。实际截图/录屏、公开站点 URL 和账号 UID 将在开发和发布后据实补齐，不能提前声称已具备。

## 本轮执行方式

先读 SDK 接口并实现可运行的后端最小链路，再完成 UI、测试、运行说明和展示页。遇到明确阻塞如账号额度不足、权限拒绝或无法安装依赖，请报告实际错误及已完成内容，不伪装完成。保持一个 Qoder 开发会话，保存可核对记录。
